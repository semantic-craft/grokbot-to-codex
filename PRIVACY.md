# Privacy and local data

GrokBot to Codex is a local bridge and skill package. The maintainer operates no hosted task service for it. This package adds no telemetry or cloud relay; the bridge listens on loopback and requires a locally stored bearer token.

The default `<installation>/.bridge/` directory contains that token, connection information, registered project names and canonical paths, task identifiers, status and model results. An explicit `BRIDGE_STATE_DIR` changes its location. Startup restricts this directory to its owner and its state files to owner read/write permissions, including files from earlier installations. Task discovery returns summary metadata; only a selected task read returns its answer. Titles and paths can still be sensitive. This state is excluded from Git and should not be included in plugin archives or support reports. The bridge does not copy or print Codex login credentials; official Codex uses its existing authentication.

This is not offline inference. Tasks and the context official Codex uses are sent to its model service. When Grok Bot or Cursor queries projects, task summaries or results, that information enters the client's conversation and may be processed by its model service. Installation settings saved in the host's skill library are also held by that host. Each application's own privacy terms and account settings govern that processing. Official Codex separately stores the conversation history used by Desktop; this package does not replace or delete that store.

The Bot Marketplace skill and portable template are generic authoring source. Each recipient discovers and configures their own Mac, installation and target projects. Publish the repository source, not a configured skill copied from an account. `npm run package:plugin` stages an explicit list of distribution files and excludes local state, Git history, research and acceptance records. It rejects symlinked source, personal home paths and recognizable API-key strings in text source. This check is a guard against common mistakes, not a universal sensitive-data detector; review any new distributable content before publication.

You can stop the bridge and disable the host skill/plugin. Retain local bridge state to keep its task index, or delete your own state directory after stopping the service if you no longer need it. Removing bridge state does not remove official Codex conversation history; manage that separately in Codex. Avoid sharing tokens, private task contents or authentication files when reporting an issue.

This notice describes the package's current local behavior, not a guarantee about the privacy practices of Grok, Cursor, Codex or their model providers.
